# Supabase Setup Guide

This document describes the future Supabase setup for the birthday website.

Do not implement this during the initial website development.

---

## 1. Create Supabase Project

Create a new Supabase project specifically for the birthday website.

Suggested project name:

```text
birthday-website
```

Keep the project private.

Save:

```text
Project URL
Anon/Public Key
```

Do not commit credentials to Git.

---

# 2. Storage

Create a storage bucket:

```text
birthday-assets
```

The bucket can contain:

```text
photos/
songs/
```

Structure:

```text
birthday-assets/
├── photos/
│   ├── photo-01.jpg
│   ├── photo-02.jpg
│   ├── photo-03.jpg
│   ├── photo-04.jpg
│   └── photo-05.jpg
│
└── songs/
    ├── song-01.mp3
    ├── song-02.mp3
    ├── song-03.mp3
    └── song-04.mp3
```

Use appropriately compressed images.

Avoid uploading unnecessarily large originals.

---

# 3. Photos Table

Create:

```sql
create table photos (
  id bigint generated by default as identity primary key,
  file_path text not null,
  caption text,
  sort_order integer not null default 0,
  active boolean not null default true,
  created_at timestamptz not null default now()
);
```

Example:

```text
id: 1
file_path: photos/photo-01.jpg
caption: null
sort_order: 1
active: true
```

---

# 4. Songs Table

Create:

```sql
create table songs (
  id bigint generated by default as identity primary key,
  title text not null,
  artist text,
  file_path text not null,
  sort_order integer not null default 0,
  active boolean not null default true,
  created_at timestamptz not null default now()
);
```

Example:

```text
id: 1
title: Example Song
artist: Example Artist
file_path: songs/song-01.mp3
sort_order: 1
active: true
```

---

# 5. Optional Site Content Table

If content eventually needs to be managed without changing code, create:

```sql
create table site_content (
  id bigint generated by default as identity primary key,
  content_key text unique not null,
  content_value text not null,
  updated_at timestamptz not null default now()
);
```

Examples:

```text
intro_line_1
intro_line_2
color_message
ocean_message
soul_message
birthday_message
```

This is optional.

For a small personal website, keeping the emotional text in source code may actually be simpler.

---

# 6. Storage Policies

Decide whether the website should use:

### Public bucket

Simplest approach.

The website can directly access:

```text
public storage URLs
```

This is appropriate only if you're comfortable with anyone who obtains the URL being able to access the assets.

OR:

### Private bucket

Use signed URLs generated by the application.

For a personal/private birthday experience, consider a private bucket if privacy of the photographs matters.

Do not expose the Supabase service-role key in frontend code.

---

# 7. Environment Variables

Eventually the frontend will use something similar to:

```env
VITE_SUPABASE_URL=
VITE_SUPABASE_ANON_KEY=
```

Never put:

```text
SUPABASE_SERVICE_ROLE_KEY
```

into frontend code.

Never commit `.env` files containing secrets.

Add:

```text
.env
.env.local
```

to `.gitignore`.

---

# 8. Application Integration

The existing application should already have abstractions such as:

```ts
getImageUrl(photo)
getSongUrl(song)
```

Change their implementation so they retrieve Supabase Storage URLs.

Do not rewrite the visual components.

The visual components should not care whether an image comes from:

```text
/local/assets/photo-01.jpg
```

or:

```text
Supabase Storage
```

---

# 9. Uploading Real Assets

When the website is ready:

1. Create the Supabase project.
2. Create the `birthday-assets` bucket.
3. Create `photos` and `songs` folders.
4. Upload the final 4–5 photographs.
5. Upload the final soft-song playlist.
6. Insert matching records into `photos`.
7. Insert matching records into `songs`.
8. Add Supabase environment variables locally.
9. Test the website.
10. Deploy only after verifying that every image and song loads correctly.

---

# 10. Important

The initial development should NOT depend on Supabase.

The complete website must work using local dummy assets.

Supabase should be treated as the final content/storage layer, not as a dependency for designing the experience.
